# 面试预习文档生成模板（通用版）

> 适用于任意源文件集合（Obsidian Canvas、语雀笔记、讲义、Markdown 文件等），提取知识点 → 生成预习填空题。

---

## 一、任务

读取 **{源文件路径}** 下的所有文件（.md/.txt/.html/.canvas 等），以及同目录下的 `assets/` 图片目录，提取所有重要知识点，生成两份文档：

1. **预习文档（填空版）** — 学生自学使用
2. **答案文档（答案版）** — 教师 / self-check 使用

两份文档保存到 **{输出路径}**。

---

## 二、知识点提取规则

### 2.1 优先级标注（三档）

| 标记 | 含义 | 使用场景 | 放的位置 |
|---|---|---|---|
| ⭐⭐⭐ | 高频必考 | 面试必问、源文件重点强调、纠错清单中的内容 | 模块最前面 |
| ⭐⭐ | 常见考点 | 面试常问、基础知识、需要理解 | 模块中间 |
| ⭐ | 加分/了解 | 进阶内容、面试加分、工作实用 | 模块最后 |

### 2.2 来源标注格式（三种类型）

每条题目后紧跟来源，格式：

```
⭐⭐⭐ [来源：文件《xxx.md 子章节] [来源：外部 关键词] [补充：百度搜索「关键词」]
```

| 类型 | 格式 | 含义 | 示例 |
|---|---|---|---|
| 源文件内容 | `[来源：文件《xxx.md`子章节/原话`]` | 源文件中写出的内容（无论对错） | `[来源：文件《JVM内存区域.md》]` |
| 外部知识 | `[来源：外部 关键词]` | 源文件没有，从外部补充 | `[来源：外部 ZGC染色指针]` |
| 搜索扩展 | `[补充：百度搜索「关键词」]` | 需要学生自行搜索扩展 | `[补充：百度搜索「ZGC分代演进」]` |

规则：
- 多个来源用空格分隔，一条题可以有多个来源
- 外部知识的 ⭐ 标记统一为 ⭐（加分/了解），**除非该知识点本身是 ⭐⭐⭐ 且源文件确实遗漏**
- 补充内容放在对应模块的末尾，单独一个子模块标题（如 `### 补充：XX`）

### 2.3 知识点去重

同一知识点在多个源文件多处出现（如"静态变量在堆里"在 3 个文件都出现），**只出一道题**，来源标注合并：

```
⭐⭐⭐ [来源：文件《A.md》+ 文件《B.md》]
```

### 2.4 纠错题（优先使用）

如果源文件中有**错误、不准确、过时**的内容，出纠错题，**不照抄错误**：

```
（XX）❌ 源文件说法？→ ✅ 正确说法：**________**。⭐⭐⭐ [来源：文件《xxx.md》]
```

示例：
```
（109）❌ 元空间存静态变量？→ ✅ 错。JDK8+ 静态变量+字符串常量池都在 **________** 中。⭐⭐⭐ [来源：文件《方法区.md》]
```

规则：
- 如果源文件自己标注了纠错（如 `❌...✅...`），直接出纠错题
- 如果源文件没标但你知道错误，也出纠错题
- 纠错题**统一归为一个子模块**（如 `### 纠错清单`），放在对应主模块末尾
- 答案版中给出正确答案，不写错误答案

### 2.5 图片处理

**必须读取 `assets/` 目录下的所有图片**（PNG/JPEG/SVG 等），特别是数据表格、位图、架构图类图片，提取正文中没有的独特信息。

- 如果图片内容已在正文文字中描述，按文字出题即可
- 如果图片中有正文**没有**的独特信息（如 Mark Word 位布局表），可以出题但标注 `[来源：文件《xxx.md》中的图片]`

### 2.6 题干自包含

学生不看原文档也能看懂题意。题干要给出足够的上下文。

## 三、题目规范

### 3.1 题型

**统一使用填空题**，格式：

```
（序号）题干描述，需要填的关键部分是 **________**。⭐⭐⭐ [来源：...]
```

规则：
- 每题独立一行，不跨段落
- 每道题 **1~5 个空**，不超过 5 个
- 多空题用顿号分隔答案
- 选择题/判断题用 **________**（选项/判断）标注

### 3.2 编号规则

**全局连续编号**，从（1）开始到（N）结束，不跨模块跳号。

### 3.3 每题结构（固定顺序）

```
（序号）题干（含填空下划线）。⭐⭐⭐ [来源：...] [补充：...]
```

### 3.4 模块划分原则

按**知识体系的逻辑模块**划分，不是按源文件的物理分组。规则：

1. 源文件的每个分组/章节是一个候选模块
2. 相关的子组合并为一个大模块（如 JVM 的"栈"+"堆"+"方法区"合并为"JVM 内存区域"模块）
3. 每个模块内部按子模块细分（如 `### 子模块名`）
4. 模块标题用 `##`，子模块标题用 `###`

### 3.5 模块优先级排序规则

模块在文档中的排列顺序，按以下优先级从高到低：

1. **⭐⭐⭐ 密度最高的模块放最前面**（面试题出现最多的主题）
2. **源文件中篇幅大、内容多、强调次数多的模块优先**（画布中面积大/节点多，或 md 文件字数多）
3. **纠错清单中的内容所在的模块优先**（说明该模块易错，需要重点记忆）
4. **同一模块内，子模块按知识依赖关系排序**（先基础概念 → 再核心机制 → 再高级特性）

## 四、输出文件

### 4.1 预习文档（填空版）结构

```markdown
# {主题} 预习填空题

> 📌 基于 `{源文件路径}` 及外部知识整理。
>
> 📌 每题后标注：⭐ 重要程度 + 来源。目的是让你填空 → 对答案 → 面试能讲出来。
>
> 📌 ⭐⭐⭐=高频必考，⭐⭐=重要，⭐=补充了解。
>
> 📌 使用方式：直接做填空 → 对照答案版 → 错题回源文件看原内容。

---

## 模块一 · {模块名}

### {子模块名}

（1）...

### 纠错清单

（X）❌ ... → ✅ **________**。

---

## 模块二 · {模块名}

...

---

*共 N 道填空，覆盖 {主题} 模块全部重要知识点。*
*答案见同目录 `{主题}预习填空题-答案版.md`。*
```

### 4.2 答案文档（答案版）结构

```markdown
# {主题} 预习填空题 · 答案版

> 📌 对照 `{主题}预习填空题.md` 使用。
> 📌 答案加粗标注，每题附来源。

---

## 模块一 · {模块名}

### {子模块名}

| 编号 | 答案 | 来源 |
|------|------|------|
| （1） | **答案内容** | [来源：...] |
| （2） | **答案内容** | [来源：...] |

### 纠错清单

| 编号 | 答案 | 来源 |
|------|------|------|
| （X） | **正确答案** | [来源：...] |

---

## 模块二 · {模块名}

...

---

*全部 N 道填空答案已给出。*
*建议：先独立完成填空题，再对照检查，错题回看源文件对应位置。*
```

**答案版规则**：
- 使用**表格对照表**形式（编号 | 答案 | 来源），方便快速查找
- 多空题用顿号分隔答案
- 标注"外部知识补充"的题目，在答案后追加 📌 补充说明（解释为什么补充、面试怎么考）
- 标注"外部知识补充"的题目，在答案后追加 📌 补充说明（解释为什么补充、面试怎么考）
- 文档末尾附说明：参考答案可能有多种表述，核心要点正确即可

## 五、生成流程（步骤清单）

```
1. 读取所有源文件（.md/.txt/.html/.canvas 等）
2. 读取 assets/ 目录下所有图片，提取正文中没有的独特信息
3. 合并去重，按知识模块归类
4. 按优先级规则排序模块（⭐⭐⭐密度 → 源文件篇幅 → 纠错内容 → 知识依赖）
5. 为每个知识点生成填空题（独立一行，含下划线、⭐、来源）
6. 纠错题统一归为"纠错清单"子模块
7. 生成答案版（表格对照表形式）
8. 检查：题号连续、来源完整、无重复考点、覆盖率 100%
```

---

## 六、质量检查清单

生成后逐项检查：

- [ ] 每题独立一行，不跨段落
- [ ] 每道题 1~5 个空，不超过 5 个
- [ ] 每题有 ⭐ 标记（⭐⭐⭐/⭐⭐/⭐）
- [ ] 每题有 [来源：...] 标注
- [ ] 编号全局连续，无跳号
- [ ] 无重复考点（同一知识点只出一道题）
- [ ] 模块按优先级排序（⭐⭐⭐ 多的在前，纠错清单在前）
- [ ] 答案版题号与题目版一一对应
- [ ] 答案准确，与源文件/权威知识一致
- [ ] 源文件有错的内容已改为纠错题，不照抄错误
- [ ] 源文件缺失的重要知识点已补充，来源标注"外部"或"百度搜索"
- [ ] 文件名符合规范

---

## 七、覆盖率核对

生成文档后，逐项核对每个源文件的核心知识点是否都被覆盖，输出核对报告：

```
## 覆盖率核对报告

| 源文件 | 覆盖题号 | 是否覆盖 |
|---|---|---|
| file1.md | (1),(2) | ✅ |
| file2.md | (3) | ✅ |
| ... | ... | ... |

遗漏知识点：（如有，补充题目后更新）
```

如果发现有遗漏，补充题目并更新两份文档。

## 八、完整单题示例

```markdown
（16）JDK 8 中 static 静态变量存在 **________** 中。⭐⭐⭐ [来源：文件《方法区.md》+ 文件《内存区域.md》]
```

拆解：
- `（16）` → 全局第 16 题
- `JDK 8 中 static 静态变量存在` → 题干上下文
- `**________**` → 填空下划线（加粗）
- `中。` → 题干结束
- `⭐⭐⭐` → 重要性标记
- `[来源：文件《方法区.md》+ 文件《内存区域.md》]` → 来源标注（两个文件都提到了，合并）

答案版对应行：
```markdown
| （16） | **堆（Java 堆）** | [来源：文件《方法区.md》+ 文件《内存区域.md》] |
```

# 预习单生成规范

> 本文档定义从画布/讲义提取知识点 → 生成预习填空题的完整流程和规范，保证每次产出格式一致。

---

## 一、输入

### 1.1 来源文件
- **主来源**：Obsidian Canvas 画布文件（`.canvas`），包含模块分组 + 文本节点 + 图片节点
- **辅助来源**：配套的 `.md` 文件（如有，如补充讲义、诊断报告等）

### 1.2 输入后先做的事
1. 解析 Canvas JSON，定位模块分组（`group` 节点，通过 `label` 识别）
2. 提取该分组下所有 `text` 节点（文本内容）和 `file` 节点（嵌入图片）
3. 提取辅助 `.md` 文件中的知识点
4. 合并去重，按知识模块归类

---

## 二、知识点整理规则

### 2.1 优先级标注（三档）

| 标记 | 含义 | 使用场景 |
|------|------|----------|
| ⭐⭐⭐ | 高频必考 | 面试必问、画布重点强调、纠错清单中的内容 |
| ⭐⭐ | 常见考点 | 面试常问、基础知识、需要理解 |
| ⭐ | 加分/了解 | 进阶内容、面试加分、工作实用 |

### 2.2 来源标注格式

每题后紧跟来源，格式：

```
⭐⭐⭐ [来源：画布 模块名/子组名/原话内容] [来源：外部 知识点关键词]
```

规则：
- 画布来源：精确到子组名或原话内容（用反引号包原话）
- 外部知识：用 `[来源：外部 知识点关键词]` 标注
- 多个来源用空格分隔
- 需要学生自行搜索扩展的：`[补充：百度搜索「关键词」]`

### 2.3 知识点去重

同一知识点在画布多处出现（如 JVM 的"静态变量在堆里"在方法区子组和纠错清单都出现），**只出一道题**，来源标注合并。

### 2.4 画布内容有误的处理

画布中的笔记可能有错误（如 JVM 画布里"元空间存静态变量"、"程序计数器用于编译优化"、"G1 不适合低延迟"等），按以下规则处理：

**原则：不照抄错误，出纠错题，让学生填正确答案。**

```
（序号）❌ 画布说法？→ ✅ 正确说法：**________**。⭐⭐⭐ [来源：画布 XX 子组（需纠错）]
```

示例：
```
（109）❌ 元空间存静态变量？→ ✅ 错。JDK8+ 静态变量+字符串常量池都在 **________** 中。⭐⭐⭐ [来源：画布 JVM 调优区]
```

规则：
- 如果画布自己标注了纠错（如 `❌...✅...`），直接出纠错题
- 如果画布没标注但你知道错误，也出纠错题，来源标注"画布 XX 子组"
- 纠错题统一归为一个子模块（如 `### 纠错清单`），放在该模块末尾，方便学生集中记忆
- 答案版中给出正确答案，不写错误答案

### 2.5 画布缺失重要信息的处理

画布可能遗漏重要知识点（如 JVM 画布缺了 TLAB、ZGC、finalize 自救等），按以下规则处理：

**原则：补充进题目，来源标注"外部知识"或"百度搜索"，不伪装成画布内容。**

```
（序号）补充知识点的题干，需要填的关键部分是 **________**。⭐ [来源：外部 知识点关键词]
```

规则：
- 补充内容的 ⭐ 标记统一为 ⭐（加分/了解），除非该知识点本身是 ⭐⭐⭐ 且画布确实遗漏
- 来源标注用 `[来源：外部 知识点关键词]`，不写"画布 XX 子组"
- 补充内容放在对应模块的末尾，单独一个子模块标题（如 `### 补充：XX`）
- 优先选权威来源（官方文档、主流技术博客）

### 2.6 来源标注的两种类型

| 类型 | 格式 | 含义 | 示例 |
|------|------|------|------|
| 画布内容 | `[来源：画布 模块名/子组名]` | 画布中写出的内容（无论对错） | `[来源：画布 JVM 区 堆子组]` |
| 外部知识 | `[来源：外部 知识点关键词]` | 画布没有，从外部补充 | `[来源：外部 ZGC 染色指针]` |

一条题可以有多个来源，用空格分隔：
```
[来源：画布 XX 子组] [来源：外部 ZGC 染色指针] [补充：百度搜索「关键词」]
```

### 2.7 画布纠错的处理方式

画布中的笔记可能有错误，但画布不一定有专门的"纠错清单"模块。错误可能散落在任意子组中，也可能根本没标出来。

**处理方式：不单独设"画布纠错"来源类型，统一用 `[来源：画布 XX 子组名]`，但题目本身出成纠错题。**

```
（序号）❌ 画布说法？→ ✅ 正确说法：**________**。⭐⭐⭐ [来源：画布 XX 子组]
```

示例：
```
（109）❌ 元空间存静态变量？→ ✅ 错。JDK8+ 静态变量+字符串常量池都在 **________** 中。⭐⭐⭐ [来源：画布 JVM 调优区]
```

规则：
- 来源标注统一用 `[来源：画布 XX 子组名]`，不区分"纠错"
- 如果画布自己标了 `❌...✅...`，直接出纠错题
- 如果画布没标但你知道错误，也出纠错题，来源标注画布内容所在的子组
- 纠错题统一归为一个子模块（如 `### 纠错清单`），放模块末尾
- 答案版中给出正确答案，不写错误答案

## 三、题目规范

### 3.1 题型

**统一使用填空题**，格式：

```
（序号）题干描述，需要填的关键部分是 **________**。⭐⭐⭐ [来源：...]
```

规则：
- 每题独立一行，不跨段落
- 一个空只考一个关键词
- 如果一道题有多个空，用（序号）统一编号
- 题干给出足够的上下文，让学生知道在考什么

### 3.2 编号规则

- 按模块内独立编号，从（1）开始
- 模块一用（1）-（N1），模块二用（1）-（N2），不跨模块连续编号
- 编号放在题首，括号包裹

### 3.3 每题结构（固定顺序）

```
（序号）题干（含填空下划线）。⭐⭐⭐ [来源：...] [补充：...]
```

示例：
```
（16）JDK 8 中 static 静态变量存在 **________** 中。⭐⭐⭐ [来源：画布 JVM 区 `jdk17 类的静态变量存在jvm中哪个区域？` + 调优区纠错清单]
```

### 3.4 模块划分原则

按知识体系的逻辑模块划分，不是按画布的物理分组。规则：

1. 画布的每个 `group` 子组是一个候选模块
2. 相关的子组合并为一个大模块（如 JVM 的"栈"+"堆"+"方法区"+"执行引擎"合并为"JVM 内存区域"模块）
3. 每个模块内部按子模块细分（如 1.1、1.2、1.3）
4. 模块标题用 `###`，子模块标题用 `####`

## 四、输出文件

### 4.1 文件名规范

```
{序号}OB{模块名称}预习填空题.md
{序号}OB{模块名称}预习填空题答案.md
```

- **序号**：三位数字，从 001 开始递增，每次生成新主题时递增（001、002、003...）
- **OB**：固定大写，紧跟序号，表示来源为 Obsidian Canvas 画布
- **模块名称**：画布中的模块分组名（如 Spring家族、JVM、多线程）
- 各部分**直接拼接，不加连字符或空格**；题目版以 `预习填空题` 结尾，答案版以 `预习填空题答案` 结尾
- 示例：`001OBSpring家族预习填空题.md` / `001OBSpring家族预习填空题答案.md`、`002OBJVM预习填空题.md` / `002OBJVM预习填空题答案.md`

### 4.2 填空题文档结构（固定）

**文档头必须标注源资料**：放在标题下方第一块，题目版与答案版都要有，写明「哪个路径下的哪个文件的哪个模块」，三要素缺一不可。格式固定为：

```markdown
> 📂 **源资料**
> - **所在路径**：`{画布文件所在目录的绝对路径}`（项目内相对路径 `{相对目录}/`）
> - **源文件**：`{画布文件名}.canvas`
> - **参考模块**：画布顶层分组 `{模块 group 的 label}`（含其下全部子分组、文本笔记、嵌入图片）
> - **辅助讲义**：`{讲义相对路径}`（如有，多份用顿号并列）
```

完整结构：

```markdown
# {序号}OB · {主题} 模块 · 预习填空题

> 📂 **源资料**
> - **所在路径**：`{画布文件所在目录的绝对路径}`（项目内相对路径 `{相对目录}/`）
> - **源文件**：`{画布文件名}.canvas`
> - **参考模块**：画布顶层分组 `{模块 group 的 label}`（含其下全部子分组、文本笔记、嵌入图片）

> 📌 基于 `{画布文件名}` 画布 {主题} 模块（含 X 条文本笔记、Y 张嵌入图片）及外部知识整理。
>
> 📌 每题后标注：⭐ 重要程度 + 来源。目的是让你填空 → 对答案 → 面试能讲出来。
>
> 📌 使用方式：直接做填空 → 对照答案版 → 错题回画布看原笔记。

---

## 模块一 · {模块名}

### {子模块名}

（1）...

---

## 模块二 · {模块名}

...

---

*共 N 个填空，覆盖 {主题} 模块全部重要知识点。*
*答案见同目录 `{序号}OB{主题}预习填空题答案.md`。*
```

### 4.3 答案版文档结构（固定）

```markdown
# {序号}OB · {主题} 模块 · 预习填空题 · 答案版

> 📂 **源资料**
> - **所在路径**：`{画布文件所在目录的绝对路径}`（项目内相对路径 `{相对目录}/`）
> - **源文件**：`{画布文件名}.canvas`
> - **参考模块**：画布顶层分组 `{模块 group 的 label}`（含其下全部子分组、文本笔记、嵌入图片）
> - **辅助讲义**：`{讲义相对路径}`（如有）

> 📌 对照 `{序号}OB{主题}预习填空题.md` 使用。
> 📌 答案加粗标注，每题附来源。

---

## 模块一 · {模块名}

> 💬 **口述框架**：{该模块面试怎么展开讲：一句话定义 → 关键机制 → 常见追问 → 易错点}

### {子模块名}

| 编号 | 答案 | 来源 |
|------|------|------|
| （1） | **答案内容** | 画布·{子组名} |
| （2） | **答案内容** | 外部·{关键词} |

---

## 模块二 · {模块名}

...

---

*全部 N 个填空答案已给出。*
*建议：先独立完成填空题，再对照检查，错题回看画布对应位置。*
```

## 五、模块优先级排序规则

模块在文档中的排列顺序，按以下优先级从高到低：

1. ⭐⭐⭐ 密度最高的模块放最前面
2. 画布中面积大、节点多的模块优先
3. 纠错清单中的内容所在的模块优先
4. 同一模块内，子模块按知识依赖关系排序（先基础后深入）

---

## 六、生成流程（步骤清单）

```
1. 解析 Canvas JSON，定位目标模块分组
2. 提取所有 text 节点（文本）和 file 节点（图片）
3. 读取辅助 .md 文件（如有）
4. 合并去重，按知识模块归类（画布内容 + 外部知识补充）
5. 按优先级规则排序模块
6. 为每个知识点生成填空题（独立一行，含下划线、⭐、来源）
7. 生成答案版（按模块+编号对照表）
8. 检查：题号连续、来源完整、无重复考点
```

---

## 七、质量检查清单

生成后逐项检查：

- [ ] 每题独立一行，不跨段落
- [ ] 每题有 ⭐ 标记（⭐⭐⭐/⭐⭐/⭐）
- [ ] 每题有 [来源：...] 标注
- [ ] 编号按模块内独立编号，连续无缺
- [ ] 无重复考点（同一知识点只出一道题）
- [ ] 模块按优先级排序（⭐⭐⭐ 多的在前）
- [ ] 答案版题号与题目版一一对应
- [ ] 答案准确，与画布/讲义原文一致
- [ ] 画布有错的内容已改为纠错题，不照抄错误
- [ ] 画布缺失的重要知识点已补充，来源标注"外部"或"百度搜索"
- [ ] 文件名符合 `{序号}OB{模块名称}预习填空题.md` 规范（答案版为 `{序号}OB{模块名称}预习填空题答案.md`，直接拼接无连字符）
- [ ] 文档头已标注源资料（所在路径 / 源文件 / 参考模块，题目版与答案版都要有；有辅助讲义时一并列出）
- [ ] 答案版为「编号 | 答案 | 来源」三列，每题来源与题目版一致且无空项
- [ ] 答案版每个大模块下有 💬 口述框架（一句话定义 → 关键机制 → 常见追问 → 易错点）

## 八、示例（完整单题）

```markdown
（16）JDK 8 中 static 静态变量存在 **________** 中。⭐⭐⭐ [来源：画布 JVM 区 `jdk17 类的静态变量存在jvm中哪个区域？` + 调优区纠错清单]
```

拆解：
- `（16）` → 模块内第 16 题
- `JDK 8 中 static 静态变量存在` → 题干上下文
- `**________**` → 填空下划线（加粗）
- `中。` → 题干结束
- `⭐⭐⭐` → 重要性标记
- `[来源：画布 JVM 区 \`jdk17 类的静态变量存在jvm中哪个区域?\` + 调优区纠错清单]` → 来源标注

答案版对应行：
```markdown
| （16） | **堆** |
```

## A · Java 基础（10）

### 🔥 1. HashMap 底层结构
- **一句话**：数组 + 链表 + 红黑树；链表长度 ≥ 8 且数组长度 ≥ 64 才树化，≤ 6 退化回链表。
- **必考原因**：集合面试开场题，后面扩容、并发、树化全挂在这句上。
- **回查**：`004 模块一 · 集合体系与 HashMap`

### 🔥 2. JDK7 扩容死循环与 JDK8 的修复
- **一句话**：JDK7 头插 transfer 在并发下会形成环形链表；JDK8 改尾插修掉了死循环，但 **HashMap 依然线程不安全**，并发要用 ConcurrentHashMap。
- **必考原因**：几乎必问的追问链，且「尾插 = 线程安全」是最常见的错误答案。
- **回查**：`004 模块一 · JDK7 transfer / 尾插法 / 纠错题`

### 🔥 3. ConcurrentHashMap 两代实现
- **一句话**：JDK7 用 Segment 分段锁；JDK8 摒弃分段锁，空桶用 CAS 无锁写入、非空桶对桶头加 synchronized。
- **必考原因**：「CHM 怎么做到线程安全」的标准答案，也是 CAS 落地的最好例子。
- **回查**：`004 模块一 · ConcurrentHashMap`

### 🔥 4. equals / hashCode 契约
- **一句话**：equals 相等则 hashCode 必须相等；HashMap 先用 hashCode 定位桶、再用 equals 精确校验；用到哈希容器就必须两个一起重写。
- **必考原因**：高频且能顺带问出哈希查找两步，答不全直接减分。
- **回查**：`004 模块一 · equals 与 hashCode`

### 🔥 5. String 为什么不可变
- **一句话**：内部 value 数组被 `final` 修饰且无对外修改入口；频繁拼接用 StringBuilder（可变、非线程安全）或 StringBuffer（同步）。
- **必考原因**：不可变性是常量池、线程安全、hash 缓存三个话题的共同前提。
- **回查**：`004 模块二 · String 与字符串常量池`

### 🔥 6. 字符串常量池与 `new String("x")`
- **一句话**：编译期把字面量放进常量池，运行期 `new` 在堆里另建一个对象；`intern()` 返回常量池中的引用；所以 `new String("x") == "x"` 为 false。
- **必考原因**：「创建了几个对象」的经典题，也是 JVM 方法区/堆迁移的衔接点。
- **回查**：`004 模块二 · 常量池 / intern`

### 🔥 7. ArrayList vs LinkedList
- **一句话**：ArrayList 是动态数组，随机访问 O(1)、中间插入 O(n)；LinkedList 是双向链表，插入 O(1)、随机访问 O(n)。
- **必考原因**：看似简单，常被用来追问扩容倍数与时间复杂度。
- **回查**：`004 模块一 · List 特点与实现`

### 🔥 8. 反射与获取 Class 的三种方式
- **一句话**：运行时获取自身信息并操作类/方法/字段；`obj.getClass()`、`Class.forName("全类名")`、`类名.class`。
- **必考原因**：Spring IOC、AOP、动态代理的底层都是反射，不讲反射讲不清框架。
- **回查**：`004 模块三 · 反射与 AOP`

### 🔥 9. 受检异常与 lambda
- **一句话**：Error / RuntimeException 是非受检，其余受检；JDK 内置函数式接口不声明 throws，lambda 里抛受检异常要自己捕获，或自定义接口声明 throws。
- **必考原因**：写 Stream 时踩过才知道，属于"用过才答得出"的区分题。
- **回查**：`004 模块三 · Lambda / 模块五 · 异常体系`

### 🔥 10. TreeSet / LinkedHashMap 的底层
- **一句话**：TreeSet 底层是 TreeMap（红黑树，按大小有序）；LinkedHashMap 用双向链表维护插入顺序。
- **必考原因**：集合体系手写图里最容易被忽略的两个实现。
- **回查**：`004 模块一 · Set 实现类`

## B · 并发（10）

### 🔥 11. 进程 / 线程与线程安全前提
- **一句话**：进程是资源分配最小单位，线程是 CPU 调度最小单位；线程安全出问题要同时满足「有共享变量」+「多线程读写它」。
- **必考原因**：整场并发面试的定义题，后面所有锁都从这里推。
- **回查**：`002 模块一 · 线程安全基础`

### 🔥 12. 三大特性
- **一句话**：原子性（不可分割）、可见性（改了别人立刻看到）、有序性（禁止指令重排）。
- **必考原因**：volatile、synchronized、JMM 全靠这三个词组织答案。
- **回查**：`002 模块一 · 三大特性`

### 🔥 13. volatile 能做什么、不能做什么
- **一句话**：保证可见性 + 禁止指令重排，**不保证原子性**；典型用法是状态标志位、双重检查锁里的单例。
- **必考原因**：最经典的半对半错题，面试官就等你说"volatile 是轻量锁"。
- **回查**：`002 模块一 · volatile`

### 🔥 14. synchronized 锁的是谁
- **一句话**：实例方法锁 `this`，静态方法锁 `Class` 对象，代码块由 `monitorenter` / `monitorexit` 实现；可重入，计数器归零才释放。
- **必考原因**：锁对象搞错，后面的死锁和锁升级题全崩。
- **回查**：`002 模块二 · synchronized 与锁升级`

### 🔥 15. 锁升级四态
- **一句话**：无锁 → 偏向锁 → 轻量级锁 → 重量级锁；Mark Word 记录状态，偏向锁 JDK15 起默认禁用。
- **必考原因**：synchronized "慢不慢"的标准答案，能顺带带出对象头。
- **回查**：`002 模块二 · 锁升级` / `005 模块一 · Mark Word`

### 🔥 16. CAS 与原子类
- **一句话**：Compare-And-Swap 乐观无锁，配合自旋；`AtomicInteger.incrementAndGet()` 替代 `++`；要留意 ABA 问题。
- **必考原因**：无锁化的基础，也是 CHM、AQS 的前置知识。
- **回查**：`002 模块三 · CAS 原子类`

### 🔥 17. 死锁四个必要条件
- **一句话**：互斥、不可剥夺、请求与保持、循环等待；破坏任一条即可避免。
- **必考原因**：定位线上卡死时的分析框架。
- **回查**：`002 模块三 · 死锁`

### 🔥 18. wait / notify
- **一句话**：`wait()` 属于 Object，调用时**释放**持有的锁；`notify()` 不释放锁；必须在 synchronized 块里调用。
- **必考原因**：和 `sleep()` 对比是必问题（sleep 不释放锁）。
- **回查**：`002 模块三 · 线程通信`

### 🔥 19. ThreadLocal 与内存泄漏
- **一句话**：每个线程一份变量副本；Entry 的 key 是弱引用，key 被回收后 value 仍在，**必须 `remove()`**，尤其在线程池里。
- **必考原因**：真实线上事故高频来源，也是「为什么线程池 + ThreadLocal 会串数据」的答案。
- **回查**：`002 模块五 · ThreadLocal`

### 🔥 20. 线程池七参数与拒绝策略
- **一句话**：核心线程数、最大线程数、空闲存活时间、时间单位、阻塞队列、线程工厂、拒绝策略；四种拒绝策略 Abort / CallerRuns / Discard / DiscardOldest。
- **必考原因**：几乎必问，且能一路追问到队列选择和生产参数怎么配。
- **回查**：`002 模块七 · 线程池 ThreadPoolExecutor`

## C · JVM（10）

### 🔥 21. 运行时数据区：私有 3 / 共享 2
- **一句话**：线程私有 = 程序计数器、虚拟机栈、本地方法栈；线程共享 = 堆、方法区（JDK8 起元空间实现）。
- **必考原因**：JVM 第一题，也是「哪些区会 OOM」的前提。
- **回查**：`005 模块一 · 运行时数据区`

### 🔥 22. 程序计数器为什么不会 OOM
- **一句话**：记录当前线程字节码行号，线程私有、随线程生灭，是唯一不抛 OutOfMemoryError 的区域。
- **必考原因**：小但高频，用来验证是不是真懂内存分区。
- **回查**：`005 模块一 · 程序计数器`

### 🔥 23. 堆的分代与对象晋升
- **一句话**：新生代 Eden : From : To = 8 : 1 : 1；新对象先在 Eden，熬过一次 Minor GC 年龄 +1，默认 15 岁晋升老年代；大对象可直接进老年代。
- **必考原因**：GC 调优题的共同起手式。
- **回查**：`005 模块一 · 堆与分代`

### 🔥 24. 对象头 Mark Word
- **一句话**：存放哈希码、GC 年龄、锁标志位、线程 ID，随锁状态在四态间变化；数组对象头还多一个「数组长度」。
- **必考原因**：把 Java 基础、并发、JVM 三块串起来的那一个结构。
- **回查**：`005 模块一 · 对象布局`

### 🔥 25. 元空间与永久代
- **一句话**：JDK8 用元空间（本地内存）替代永久代；类元数据在元空间，静态变量和字符串常量池在**堆**里。
- **必考原因**：画布上原本记错了（写成元空间存静态变量），是纠错清单重点。
- **回查**：`005 模块一 · 方法区与元空间` / `模块六 · 纠错清单`

### 🔥 26. 类加载五阶段
- **一句话**：加载 → 验证 → 准备 → 解析 → 初始化；**准备阶段只赋零值**，真实赋值在 `<clinit>` 初始化阶段；解析把符号引用换成直接引用。
- **必考原因**：「准备阶段赋不赋值」是经典陷阱。
- **回查**：`005 模块二 · 类加载机制`

### 🔥 27. 双亲委派
- **一句话**：子加载器先层层向上委托，父加载器能加载就加载；好处是避免类重复加载、保证核心类库安全；自定义加载器重写 `findClass` 而非 `loadClass`。
- **必考原因**：类加载模块唯一必背，常接 Tomcat 类加载器隔离追问。
- **回查**：`005 模块二 · 双亲委派`

### 🔥 28. GC Roots 与可达性分析
- **一句话**：从 GC Roots（栈局部变量、JNI 引用、类静态变量、方法区常量、同步锁持有对象）出发，引用链不可达即判为垃圾；引用计数解决不了循环引用。
- **必考原因**：所有 GC 算法的基础。
- **回查**：`005 模块三 · 对象存活判断`

### 🔥 29. 三色标记 / CMS / G1 / ZGC
- **一句话**：CMS 与 G1 都基于三色标记；CMS 老年代用标记-清除（有碎片、有浮动垃圾）；G1 把堆切成多个 Region、逻辑分代，做 Mixed GC；ZGC 停顿 < 1ms 且不随堆增长。
- **必考原因**：收集器对比是 JVM 面试的主战场，画布把 ZGC 写成 10ms，正确是 <1ms。
- **回查**：`005 模块三 · 三色标记` / `模块四 · 垃圾收集器`

### 🔥 30. 调优工具链与 OOM 定位
- **一句话**：`jstat -gcutil` 看 GC 统计、`jmap` / `jstack` / `jcmd` / Arthas 定位；配 `HeapDumpOnOutOfMemoryError` 在 OOM 时才 dump；OOM 要分堆、元空间、栈、直接内存四种成因。
- **必考原因**：「线上 OOM 你怎么排查」的标准流程题。
- **回查**：`005 模块五 · JVM 调优`

## D · Spring 家族（10）

### 🔥 31. IOC / DI / BeanDefinition
- **一句话**：IOC 把对象创建与依赖管理的控制权交给容器；DI 是 IOC 的实现方式；扫描后把类信息封装成 BeanDefinition（"图纸"）存进 `beanDefinitionMap`，**它不是对象**。
- **必考原因**：Spring 面试的定义题，后面生命周期、后置处理器都建立在这三个词上。
- **回查**：`001 模块一 · IOC 容器与 Bean 生命周期`

### 🔥 32. Bean 生命周期五阶段
- **一句话**：实例化 → 属性填充 → 初始化 → 使用中 → 销毁；入口是 `ApplicationContext.refresh()`，真正实例化非懒加载单例在 `finishBeanFactoryInitialization`；初始化回调顺序 `@PostConstruct` → `afterPropertiesSet()` → `init-method`。
- **必考原因**：最高频的 Spring 大题，能一路追问到销毁顺序。
- **回查**：`001 模块一 · Bean 生命周期`

### 🔥 33. 三级缓存与循环依赖
- **一句话**：`singletonObjects`（成品）/ `earlySingletonObjects`（半成品）/ `singletonFactories`（对象工厂）；**只解决单例 + setter/字段注入**的循环依赖，构造器注入解决不了。
- **必考原因**：Spring 八股之王，答不出三级缓存基本等于没准备 Spring。
- **回查**：`001 模块二 · 三级缓存与循环依赖`

### 🔥 34. 构造器注入 vs 字段注入
- **一句话**：官方推荐构造器注入——依赖可加 `final`、不可变、启动时就暴露循环依赖；字段注入被 IDEA 不推荐，且容易隐藏循环依赖。
- **必考原因**：常和上一题连着问，用来验证是否真理解「为什么构造器注入反而解决不了循环依赖」。
- **回查**：`001 模块一 · DI 三种注入方式`

### 🔥 35. 两大后置处理器
- **一句话**：`BeanFactoryPostProcessor` 作用于 **BeanDefinition**（还没实例化，典型是 ConfigurationClassPostProcessor）；`BeanPostProcessor` 作用于**每个 Bean 实例**，AOP 代理就在 `postProcessAfterInitialization` 里生成。
- **必考原因**：把「扫描 → 图纸 → 实例化 → 代理」这条链串起来的关键。
- **回查**：`001 模块一 · 后置处理器` / `模块三 · AOP`

### 🔥 36. AOP 与动态代理
- **一句话**：把日志、权限、监控、事务等横切逻辑抽到独立模块；Spring AOP 是**运行期织入**（JDK 动态代理走接口、CGLIB 走子类），AspectJ 才支持编译期/类加载期织入。
- **必考原因**：AOP 是事务的底层，不讲代理讲不清事务为什么会在自调用时失效。
- **回查**：`001 模块三 · AOP 面向切面编程`

### 🔥 37. `@Transactional` 的本质
- **一句话**：事务就是一个切面，注解被 AOP 识别后给 Bean 加事务增强；事务状态绑定在 **ThreadLocal** 上，同线程调用才能传播。
- **必考原因**：把 Spring、AOP、并发三块连起来的题。
- **回查**：`001 模块四 · Spring 事务`

### 🔥 38. 事务失效的常见场景
- **一句话**：同类内部 `this` 自调用绕过代理、方法内吞掉异常没抛、非 `public` 方法、异常类型不匹配 `rollbackFor`、跨线程调用（ThreadLocal 不共享）。
- **必考原因**：生产事故复现题，几乎每个后端都踩过其中一条。
- **回查**：`001 模块四 · 事务失效场景`

### 🔥 39. SpringBoot 自动配置
- **一句话**：`@EnableAutoConfiguration` 通过 `AutoConfigurationImportSelector` 读取 starter 的 imports 清单；2.7+ 用 `META-INF/spring/…AutoConfiguration.imports` 替代旧 `spring.factories`；官方 starter 共用一份清单，不是各自带一份。
- **必考原因**：「starter 为什么引一个依赖就能用」的标准答案，也是画布纠错点。
- **回查**：`001 模块六 · SpringBoot 核心原理`

### 🔥 40. Bean 作用域与单例线程安全
- **一句话**：singleton（默认）、prototype、request、session、application；单例 Bean **无状态才线程安全**，有成员变量就要用 ThreadLocal 或改 prototype。
- **必考原因**：直接和并发模块联动的高频追问。
- **回查**：`001 模块五 · Bean 作用域`

## E · Tomcat 与网络（10）

### 🔥 41. Web 容器 vs Spring 容器
- **一句话**：Spring 容器管 Bean 与依赖；Web 容器（Tomcat）跑 Web 应用、管 Servlet 生命周期；**请求先到 Tomcat**，再由它交给 SpringMVC 找 Controller。
- **必考原因**：一次请求链路题的起点，很多人把两个容器混着答。
- **回查**：`003 模块一 · Web 容器与 Tomcat 架构`

### 🔥 42. Tomcat 两大核心组件
- **一句话**：Connector 负责监听端口、解析 HTTP 报文（默认 8080）；Container 负责 Servlet 生命周期与业务分发；HTTP 服务器**不认识 Controller**。
- **必考原因**：Tomcat 架构唯一必背。
- **回查**：`003 模块一 · Connector / Container`

### 🔥 43. 一次 HTTP 请求的完整链路
- **一句话**：浏览器 → Connector 解析报文 → Container → DispatcherServlet → HandlerMapping（含 Interceptor）→ Controller → 视图/响应。
- **必考原因**：把 Tomcat、SpringMVC、拦截器顺序一网打尽的串联题。
- **回查**：`003 模块六 · 一次 HTTP 请求的完整链路`

### 🔥 44. GET vs POST
- **一句话**：GET 参数拼在 URL 后、幂等、用于查询；POST 参数放 body、非幂等、用于新增；**两者本身都不加密**，只有 HTTPS 下才都加密，GET 因参数留在 URL/日志/历史里更易泄漏。
- **必考原因**：画布上"POST 更安全/会加密"是错的，纠错清单重点。
- **回查**：`003 模块二 · HTTP 协议基础`

### 🔥 45. 状态码、转发与重定向、304
- **一句话**：1xx 信息 / 2xx 成功 / 3xx 重定向 / 4xx 客户端错 / 5xx 服务端错；转发是服务端内部跳转、**1 次**请求，重定向返回 302 由浏览器再发、**2 次**请求；304 是协商缓存命中，但仍会发请求校验。
- **必考原因**：三个知识点常被揉在一道题里问。
- **回查**：`003 模块二 · HTTP 状态码与缓存`

### 🔥 46. HTTP/1.1 长连接 vs HTTP/2
- **一句话**：`Connection: keep-alive` 让多个请求复用一条 TCP 连接，但并发仍需多连接；HTTP/2 用**多路复用**在单连接上并发处理，配合头部压缩、二进制分帧。
- **必考原因**：性能优化话题的入口。
- **回查**：`003 模块二 · HTTP 版本演进`

### 🔥 47. HTTPS = HTTP + TLS
- **一句话**：TLS 负责加密、验证身份、防篡改；**TLS 握手发生在 TCP 三次握手之后**，完成后才发 HTTP 请求。
- **必考原因**：顺序说反是常见扣分点。
- **回查**：`003 模块三 · HTTPS 与 Web 安全` / `模块四 · TCP`

### 🔥 48. 三次握手与四次挥手
- **一句话**：SYN → SYN+ACK → ACK 建连；FIN → ACK → FIN → ACK 断连；客户端最后一次 ACK 后等 **2MSL（TIME_WAIT）** 才关闭；这些由**内核 TCP 协议栈**完成，Tomcat 只等通知。
- **必考原因**：网络模块最高频，且能追问为什么是三次不是两次。
- **回查**：`003 模块四 · TCP 三次握手与四次挥手`

### 🔥 49. CSRF 为什么会发生
- **一句话**：根因是浏览器会**自动携带目标站点 Cookie**；前后端分离把 token 放 `Authorization` 请求头、不用 Cookie 就天然免疫；也可加 Referer 校验 / 双重提交。
- **必考原因**：安全题里最容易讲清因果的一条。
- **回查**：`003 模块三 · CSRF 与 Web 安全`

### 🔥 50. Tomcat NIO 与 Session
- **一句话**：默认 `Http11NioProtocol`（NioEndpoint），少量线程撑大量连接，取代早期 BIO 一连接一线程；Session 默认 30 分钟无操作超时，集群下要 Session 复制或改存 Redis。
- **必考原因**：把容器模型和登录态串起来，常作为收尾追问。
- **回查**：`003 模块一 · NIO 模式` / `模块三 · Session`

## 第一梯队 · 稳分题（画布有素材 🎯）

### Q1. JVM 运行时数据区怎么划分？哪些线程共享/私有？ 🎯

线程私有：**虚拟机栈**（栈帧：局部变量表、操作数栈、动态链接、方法出口）、**本地方法栈**（为 native 方法服务，C/C++ 实现）、**程序计数器**（记录当前字节码行号，线程切换后恢复执行位置）。
线程共享：**堆**（对象实例，GC 主战场）、**方法区**（JDK8 起由元空间实现，位于本地内存，存类元信息、运行时常量池）。

**追问：JDK8 把方法区改成了什么？** 元空间，从 JVM 内存挪到**本地内存**，不再受堆大小约束；同时 **static 变量、字符串常量池移到堆中**（你画布记过：JDK7 起 static 已迁出）。

**追问：JDK17 类的静态变量存在哪？** 堆里的 Class 对象中（你自问自答过——规范把静态变量归入方法区是逻辑概念，HotSpot 实现放堆里）。

### Q2. 说一下类加载的过程 🎯

加载（全限定名取二进制字节流入内存）→ 验证（格式/元数据/字节码/符号引用四道检查）→ 准备（**静态变量分配内存、赋零值**，int=0、引用=null——你标注过的易错点）→ 解析（符号引用→直接引用）→ 初始化（执行 `<clinit>`：静态变量真实赋值+静态代码块）。

**追问：准备和初始化的区别？** 准备给默认零值，初始化给代码里写的真实值（static int a=1：准备完是 0，初始化才变 1）。

**追问：符号引用和直接引用是什么？**（你的画布有现成通俗版）编译器不知道类会加载到哪块内存，class 文件里存的是字符串 `User.sayHello:()V`——这就是符号引用；运行到这行字节码时找到内存真实地址替换掉——直接引用，之后直接跳地址执行不再查名字。

### Q3. 什么是双亲委派？为什么要设计它？ 🎯

子加载器收到请求先层层向上委托（App→Ext→Bootstrap），父加载器能加载就加载，不能才逐层下放回子加载器。
两个好处（你记过）：①避免重复加载（父加载过的子不再加载）；②**安全**——`java.lang.String` 永远由 Bootstrap 加载，防止核心类被篡改。
生活类比（你的原版）：孙子有人找，先问爸爸，爸爸问爷爷——"爸爸干不了啊"才自己干。

**追问：怎么打破？**（🔥 补课：见 02 文档第四节）SPI/JDBC（线程上下文类加载器反向委托）、Tomcat webapp 隔离（先自己加载）、热部署（换类加载器）。**自定义类加载器重写 findClass() 而非 loadClass()**。

### Q4. 代码题：输出顺序？ 🎯（你画布的实验代码）

```java
public class Father {
    static { System.out.println("父类静态代码块"); }        // 1
    { System.out.println("父类实例代码块"); }                // 3
    public Father() { System.out.println("父类构造方法"); }  // 4
}
class Son extends Father {
    static { System.out.println("子类静态代码块"); }        // 2
    { System.out.println("子类实例代码块"); }                // 5
    public Son() { System.out.println("子类构造方法"); }    // 6
    public static void main(String[] args) {
        new Son(); System.out.println("----"); new Son();
    }
}
```

第一次 new：**父静态(1)→子静态(2)→父实例(3)→父构造(4)→子实例(5)→子构造(6)**；第二次 new：只执行 3→4→5→6（静态只加载一次）。
原理一句话：类初始化先父后子（`<clinit>` 保证），实例初始化先父后子且构造最后。

### Q5. 讲讲 ParallelGC、CMS、G1 的区别 🎯（你的对比表）

| | ParallelGC | CMS | G1 |
|--|-----------|-----|----|
| 算法 | 新生代复制+老年代整理 | 标记-清除 | Region 化，跨 Region 复制 |
| 停顿 | 全程 STW、停顿长 | 低停顿 | **可预测停顿** |
| 碎片 | 少 | 多 | 无 |
| 定位 | 高吞吐 | 低延迟（已废弃） | 低延迟+服务端默认 |

**追问：JDK8 默认哪个？** ParallelGC（你命令行验证过 `-XX:+PrintCommandLineFlags` 显示 `-XX:+UseParallelGC`——**把验证命令讲出来，面试官会记住你**）。JDK9 起服务端配置自动切 G1。

### Q6. CMS 的回收流程和缺点？ 🔥（流程是补课点）

四阶段：初始标记（STW，只标 GC Roots 直连）→ 并发标记（遍历对象图）→ 重新标记（STW，修正并发期变动）→ 并发清除。
四缺点（凑齐你缺的第 3 条）：①标记-清除**碎片**多；②**并发失败**退化为 Serial Old 长停顿；③**浮动垃圾**——并发清除期间新产生的垃圾本轮回收不到，所以要预留老年代空间提前触发；④并发阶段抢占 CPU。JDK9 废弃警告、14 彻底移除。

### Q7. G1 为什么能控制停顿时间？ 🎯（你的原理卡）

堆拆成独立小 Region（逻辑分代、物理不分代）；每次 GC 前按历史数据**估算各 Region 回收耗时和收益，动态挑选**本次回收哪些 Region，把总工作量控制在目标值内 → `-XX:MaxGCPauseMillis`（默认 200ms，是**期望值不是硬保证**）。
对比：传统 GC 一次回收整块内存，堆越大 STW 越长、不可控（你记过的原话）。

**追问：Mixed GC 是什么？** 一轮同时回收年轻 Region + 部分高收益老年代 Region（分代混合回收）——不管标记是年轻还是老，挑效率高的一次回收。

**追问：G1 的缺点？**（⚠ 标准答案）**吞吐量低于 ParallelGC**（为低延迟做的权衡）；Region 化带来维护成本（Remembered Set 额外内存）。堆太小（<4G）时 G1 优势不明显。

### Q8. GC 的并行和并发有什么区别？ 🎯（你专门记过"很多人弄混"）

**并行**：STW 暂停全部应用线程，多个 GC 线程同时干活；**并发**：GC 线程和应用线程一起跑，不 STW。
对照表：ParallelGC 全程并行无并发；CMS 并发标记+并发清除（初始/重新标记并行 STW）；G1 并发标记 + 拷贝回收 STW 并行——混合型。

### Q9. 你简历里的项目 JVM 参数是怎么设置的，为什么？ 🎯（生产实战，独家）

（你 Docker 启动命令 12 条，挑核心讲：）
- `-Xms1024m -Xmx4096m`：初始堆和最大堆；**注意容器 limit 要比 Xmx 大**（给元空间/线程栈/native 留 5~6G）
- `-XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=512m`：元空间防类加载泄漏吃光宿主机内存
- `-XX:+UseG1GC -XX:MaxGCPauseMillis=200`：低延迟业务选 G1
- `-XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/dump.hprof`：OOM 自动留现场给 MAT；**坑：容器重启 dump 丢失，必须挂载卷**
- `-Djava.security.egd=file:/dev/./urandom`：修容器熵不足导致启动慢
- `-Dfile.encoding=UTF-8`：信创麒麟环境防乱码

这套讲出来，"你真调过优"的人设立住，面试官大概率顺着深挖——继续用 02 文档 1.5 容器感知、1.3 排查链接住。

## 第二梯队 · 重点补课题（🔥）

### Q10. Minor GC / Major GC / Full GC 的触发条件？ 🔥

Eden 满 → Minor GC（快、频繁、正常）；老年代空间不足 / 元空间不足 / System.gc()（-XX:+DisableExplicitGC 可禁）/**空间分配担保失败** / CMS 并发失败 → Full GC（慢、要消灭）。
追问"分配担保"：Minor 前老年代剩余放不下新生代全部对象时，按历次晋升均值做担保判断，没把握就直接先 Full GC。

### Q11. JVM 怎么判断对象可以回收？ 🔥

引用计数法（简单但**循环引用**解不了，主流 JVM 不用）→ 可达性分析：从 GC Roots 递归扫描，引用链达不到即可回收。GC Roots 四种（你记过）：虚拟机栈局部变量、本地方法栈 JNI 引用、类静态变量、运行时常量池常量。

### Q12. 四种引用知道吗？ 🔥（画布空白，必补）

强（宁 OOM 不回收）→ 软 SoftReference（内存不足才回收，做缓存）→ 弱 WeakReference（下次 GC 必回收，**ThreadLocalMap 的 key**——串到你多线程区的 ThreadLocal 泄漏链）→ 虚 PhantomReference（get 恒 null，配引用队列，堆外内存回收通知）。

### Q13. 线上频繁 Full GC 怎么排查？ 🔥（主线题，按 02 文档 1.1-1.3 答）

jps 定位进程 → `jstat -gcutil <pid> 1000` 看 O 列和 FGC 增长 → 分情况：
回收后 O 明显回落 = 堆太小/晋升过快（调 -Xmx、MaxTenuringThreshold）；
回收后 O 不落 = 内存泄漏 → jmap 导堆快照 → MAT 看 Leak Suspects / Dominator Tree → 定位未关闭资源、长生命周期大对象、无上限缓存 → 改代码（try-with-resources、过期策略、用完 remove）。
收尾加分：先监控后调参、一次只改一个参数、GC 时间占比健康线 <10%。

### Q14. 都有哪些 OOM？怎么处理？ 🔥

堆 / Metaspace（类泄漏）/ GC overhead limit exceeded（98% 时间 GC 却回收不到 2%）/ unable to create new native thread（**减小** -Xss、调 ulimit）/ Direct buffer memory（NIO 直接内存）。
区分：内存泄漏是原因（该死不死），溢出是结果（装不下）。

### Q15. 为什么要 TLAB？ 🔥

堆共享，多线程同时分配会争抢 Eden 指针；每线程在 Eden 划私有 TLAB，分配只动指针（指针碰撞），无锁化。`-XX:+UseTLAB` 默认开。

### Q16. 对象在内存里长什么样？ 🔥（串锁升级）

对象头（Mark Word + 类型指针[+数组长度]）+ 实例数据 + 对齐填充（8 字节对齐）。Mark Word 内容随锁状态变：无锁(hashcode+年龄)→偏向(线程ID)→轻量级(栈中 Lock Record 指针)→重量级(堆中 Monitor 指针)；偏向锁 JDK15 起默认禁用。

### Q17. StackOverflowError 和 OOM 区别？ 🔥

SOFE：栈深度超限（无出口递归），调 -Xss；OOM：空间不足。递归深度 ≈ 栈容量/每帧大小。

## 第三梯队 · 加分题（⭐）

### Q18. ZGC 了解吗？ ⭐

JDK11 引入、15 生产可用；停顿 **<1ms 且不随堆大小增长**（TB 级堆也成立）；核心技术染色指针+读屏障。选择口径：堆 ≤8G 用 G1，超大堆/极致延迟用 ZGC。

### Q19. finalize 里的对象能活吗？ ⭐

不可达对象若重写了 finalize() 且没执行过，有一次自救机会（finalize 里把 this 挂回引用链）；只执行一次，JDK9 起废弃。

### Q20. JIT 和逃逸分析了解吗？ ⭐

热点代码 JIT 编译为机器码（C1 快编译/C2 深优化）；逃逸分析判定对象是否出方法 → 无逃逸可做**锁消除、标量替换**（HotSpot 实际用标量替换，无真栈上分配）。

# 典型回答

  

Spec Coding（规约编程）与 Vibe Coding（氛围编程）是当前人工智能时代两种截然不同的编程范式。它们的共同点都是使用AI Coding工具来做编程，核心区别在于驱动方式、工作流、适用场景以及工程化程度

​  

[链接](https://www.yuque.com/hollis666/xx5hr2/coedwyfzloedy1wl)

  

**Vibe Coding 是“凭感觉写代码”，而 Spec Coding 是“按标准写代码”。可以说Spec Coding是Vibe Coding的进阶版。靠Vibe Coding能提效，靠Spec Coding不仅能提效，还能写出质量更高，确定性更强的生产级代码。**

  

对于**Vibe Codi****ng**来说，开发者只需用自然语言描述一个大概的想法或感觉（如“高级一点”、“像苹果官网”），AI 就会直接生成代码雏形。开发者通过“看结果 → 说改动 → 再看”的循环来不断微调，整个过程高度依赖直觉和即时反馈。

​  

Vibe Coding一般大家使用Cursor、Codex、Claude Code就够了。

​  

**Spec Coding**强调在动手写代码之前，人类与 AI 必须先共同制定一套详细的规约文档（Spec），明确架构、功能边界、业务逻辑和验收标准。AI 会严格基于这份文档，拆解任务并逐点执行开发。

​  

Spec Coding除了上面这些AI工具，还会搭配OpenSpec、superpowers等插件。

​  

其他区别：

  

-   **需求粒度与沟通方式**：Vibe Coding 的需求通常较粗，依赖口头沟通，靠上下文记忆进行纠偏；Spec Coding 的需求极细，明确到输入输出、边界异常和验收标准，采用文档化沟通，产物可复用和交接
-   **编码节奏与容错机制**：Vibe Coding 追求“小步快跑、边写边改”，容错率高，允许频繁改变方向，适合探索未知；Spec Coding 则是“阶段推进（文档评审 → 任务执行 → 验收）”，容错率中等，改变方向需要先修改文档，避免越改越乱**​**
-   **质量保障与结果验证**：Vibe Coding 的质量依赖工程师的经验和手工验证，容易出现“能跑就行”的错觉，且结果不可复现；Spec Coding 更容易内置质量门禁，强调结果的可验证性，且每一次生成都有明确的审计链路（需求 → Spec → 代码）

**​**  

**Vibe Coding 适用场景**：快速试错、探索方向、制作原型、UI 交互打磨、小需求/临时脚本，或者你对领域非常熟悉且结果容易验收的场景。它的核心理念是“先做出来再说”

**​**  

**Spec Coding 适用场景**：新系统开发、跨多个文件/模块的复杂功能开发、系统重构、长期迭代项目以及高风险改动。它的核心理念是“先写清楚再开跑”

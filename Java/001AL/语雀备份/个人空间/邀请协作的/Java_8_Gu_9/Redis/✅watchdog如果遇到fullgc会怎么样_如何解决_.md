# 典型回答

  

watchdog后台是一个时间轮，定时执行的，但是如果到了要开始执行的时候，刚好触发了full gc，导致了STW，而STW时间又比较长的话，就会导致watchdog没能及时执行，就会导致锁被释放。

​  

如这个case：

```plain
0s   获取锁，TTL=30s
10s  正常续期，TTL重新变为30s
35s  发生Full GC
45s  STW结束，但锁已在40s左右过期
45s  Watchdog恢复并尝试续期，续期失败
```

  

Watchdog 只能保证 JVM 正常调度时自动续期。遇到这种STW期间要续期的任务，就无法处理了。

​  

那如何解决这类问题呢？

​  

首先，肯定是优先考虑减少fullgc的发生，并且降低fullgc的耗时。理论上来说，一周内出现超过一次fullgc就需要关注了，想办法解决fullgc的问题，要么是大对象太对了，要么是有太多的反序列化或者动态类创建导致的。

另外的话，就是不要100%依赖分布式锁来控并发， 其实我们也讲过，Redis实现的分布式锁他本质上是一种用性能换一致性的锁方案，他本身就无法保证100%的一致性的。所以，建议大家做好兜底，虽然发生的概率比较低，比如在数据库中做乐观锁，或者唯一性索引做约束。

# 典型回答

  

**虚拟线程提升的是“阻塞型任务的并发承载能力”**，他无法提升单任务执行速度。吞吐下降通常有以下原因：

​  

-   **任务是 CPU 密集型。**虚拟线程数量远超 CPU 核数后，会增加调度和上下文切换成本。此类任务应使用固定大小的平台线程池，线程数接近 CPU 核数。

​  

[链接](https://www.yuque.com/hollis666/xx5hr2/dye7p0b0it112wcy)

​  

-   **发生载体线程钉住**（PINNED：详见下面的链接）。虚拟线程在 synchronized、JNI、本地方法中执行阻塞操作时，可能无法卸载，导致 carrier thread 被占住。可用：

```plain
-Djdk.tracePinnedThreads=full
```

或 JFR 的 jdk.VirtualThreadPinned 事件排查。

​  

[链接](https://www.yuque.com/hollis666/xx5hr2/cdp5h287x61w7uyc)

​  

​  

-   **下游被打满**。虚拟线程放大并发后，数据库连接池、Redis、HTTP 服务、磁盘或第三方接口成为瓶颈，超时和重试进一步形成流量放大。虚拟线程不应该替代连接池、Semaphore 和限流。

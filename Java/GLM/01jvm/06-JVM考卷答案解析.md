## 五、简答题（每题 5 分，共 20 分）

### 1. 准备 vs 初始化

- **准备**：为静态变量分配内存，赋**默认零值**（int=0、引用=null），此时代码里写的值还没生效。
- **初始化**：执行 `<clinit>`，静态变量才被赋上**代码里写的真实值**，并执行静态代码块。
- 举例：`static int a = 1;` → 准备阶段 a=0，初始化阶段 a=1。

### 2. 双亲委派

- **流程**：子加载器收到请求先层层向上委托（App→Ext→Bootstrap），父能加载就加载，不能才下放回子加载器。
- **为什么**：①避免类重复加载；②保证核心类安全——java.lang.String 永远由 Bootstrap 加载，防止被篡改。

### 3. G1 可预测停顿

- 堆被拆成独立小 Region；每次 GC 前**估算各 Region 的回收耗时和收益，动态挑选**本次回收哪些 Region，把总工作量控制在目标值内。
- 通过 `-XX:MaxGCPauseMillis`（默认 200ms）设目标停顿。
- 对比：传统 GC 一次回收整块内存，堆越大 STW 越长、不可控。

### 4. 频繁 Full GC 排查

- jps 定位进程 → `jstat -gcutil <pid> 1000` 看 O 列、FGC 增长 → 分情况：
  - 回收后 O 明显回落 → 堆太小/晋升过快 → 调 -Xmx、MaxTenuringThreshold
  - 回收后 O 不降 → **内存泄漏** → `jmap -dump` 导堆快照 → MAT 看 Leak Suspects/Dominator → 定位（未关闭资源、长生命周期大对象、无上限缓存）→ 改代码
- 收尾：先监控后调参、一次只改一个参数。

## 六、代码分析题（15 分）

### 第一次 new Son() 输出顺序

```
1. 父类静态代码块
2. 子类静态代码块
3. 父类实例代码块
4. 父类构造方法
5. 子类实例代码块
6. 子类构造方法
```

（每行 1.5 分，共 9 分）

### 第二次 new Son() 少了哪些，为什么（6 分）

少了 **1、2** 两条（父类静态代码块、子类静态代码块）。
原因：**静态代码块属于类初始化，一个类只初始化一次**（`<clinit>` 只执行一次），而实例代码块和构造方法属于实例初始化，每次 new 都会执行。

**评分要点：**
- 说出"静态块只执行一次、类只初始化一次"给核心分（3 分）
- 实例块+构造每次 new 都执行（2 分）
- 顺序"父先于子"能点出根因（1 分）

## 二、逐区分析

### A. 类加载器（21 图）——掌握度：★★★★☆ 画布里最扎实的区

**已掌握（有完整证据链）：**
- 类加载全过程：加载（二进制字节码入内存）→ 链接（验证/准备/解析）→ 初始化（静态代码块、静态变量赋值），且准备阶段"设默认值"这个易错点你单独标注过
- 四类加载器的职责和各自加载路径（rt.jar / ext / classpath / 自定义）
- 双亲委派：层级图 + "父子委托"生活类比 + 两大好处（避免重复加载、核心类安全）
- **类初始化顺序实验**（父静态1→子静态2→父实例3→父构造4→子实例5→子构造6，二次 new 不再执行静态块）——这是你画布的高价值素材，面试可直接讲
- 符号引用 vs 直接引用：编译期存字符串 `User.sayHello:()V` → 运行期替换真实内存地址，理解到位

**薄弱/缺失：**
- "首次主动使用才触发类初始化"只记了一句，**6 种主动引用场景没展开**（面试爱追问："new、读写静态字段、反射、main 类、子类初始化触发父类、MethodHandle"）
- **打破双亲委派的场景没记**（SPI/JDBC、Tomcat、热部署）——中高级必问
- 双亲委派的好处你记了两条，但"如何自定义类加载器（继承 ClassLoader，重写 findClass 而不是 loadClass）"没记

### B. 运行时数据区（22 图）——掌握度：★★★☆☆ 曾困惑、现已厘清

**已掌握：**
- 整体结构图：线程共享（堆、方法区）vs 线程私有（虚拟机栈、本地方法栈、程序计数器）——本地方法栈 vs 虚拟机栈的区别（native 方法、C/C++）你单独记了
- **JDK 7/8 方法区演进**：永久代→元空间（本地内存），JDK8 拆分（static 变量→堆中 Class 对象、字符串常量池→堆）——你反复记了 3 张图，说明这里曾是困惑点，**现在你笔记里的结论是对的**：JDK17 静态变量在堆，还自问自答过
- 堆分区图（Eden/S0/S1/Old）+ Minor/Major/Full GC 的作用范围 + -Xms/-Xmx/-Xmn

**薄弱/缺失：**
- 程序计数器、执行引擎、JIT 各只有一张标题卡，没有实质内容（"硬件交互 如 系统调度"是唯一一句）——**程序计数器的作用（字节码行号指示器、线程切换恢复执行位置）没记**
- **TLAB 完全没记**（高频：为什么对象分配要 TLAB）
- **对象内存布局（对象头/实例数据/对齐填充 + Mark Word）没记**——结合多线程区的锁升级是高频组合题
- **栈溢出 StackOverflowError 没记**——你记了堆 OOM，但栈深度、-Xss、SOFE vs OOM 的对比缺失
- 直接内存没记

### C. 垃圾对象判断（3 图）——掌握度：★★☆☆☆ 画布最薄的区

**已掌握：**
- GC Roots 四种（栈中引用、JNI 引用、类静态变量、运行时常量池常量）+ 从 GC Roots 递归扫描

**薄弱/缺失：**
- **引用计数法只有标题**，它最大的考点"无法解决循环引用"没记——这是"为什么用可达性分析"的标准答案
- **四种引用（强/软/弱/虚）完全没记**——高频题，而且和多线程区的 ThreadLocal 弱引用、缓存设计直接相关，是你现有知识体系的一块明显空缺
- finalize() 与对象自救（可达性分析两次标记）没记

### D. GC 算法（11 图）——掌握度：★★★☆☆

**已掌握：**
- 三种算法及分代应用：新生代复制（清空 Eden）、老年代标记整理、CMS 标记清除易碎片——你在收集器对比表里记得很细
- Full GC 从 GC Root 出发标记可达对象

**薄弱/缺失：**
- **Minor/Major/Full GC 的触发条件没记**（画布只记了三者的作用范围箭头，没记"什么时候触发"）——面试问的是触发条件：Eden 满→Minor；老年代空间不足/元空间不足/System.gc()/空间分配担保失败→Full
- 为什么新生代用复制算法（存活率低、复制成本低）你隐含在对比表里，但没有显式结论
- 空间分配担保没记

### E. 垃圾回收器（11 图）——掌握度：★★★★☆ 近期补强、质量高

**已掌握：**
- **三收集器对比表**（ParallelGC 标记复制+标记整理/高吞吐 STW 长；CMS 标记清除/低停顿碎片多；G1 跨 Region 复制/可预测停顿无碎片）——画布高价值素材
- CMS 缺点记了 3/4：①碎片 ②并发失败触发 Serial Old 长 Full GC ④并发阶段占 CPU——**第 ③ 条"浮动垃圾"的图没截上，四条里你缺这条**
- JDK8 默认 ParallelGC 的命令行验证（-XX:+PrintCommandLineFlags）——有实操证据，面试讲得出
- G1 可预测停顿原理：MaxGCPauseMillis 目标值、Region 最小回收单元、估算耗时动态选择 Region 数量
- G1 逻辑分代物理不分代、跨 Region 拷贝、MixedGC 一轮同时回收年轻+部分老年代 Region
- JDK 默认 GC 演进表（6/7/8→ParallelGC；9~26 条件自动切 G1；14+ 移除 CMS；27+ 统一 G1）

**薄弱/缺失：**
- **CMS 四个阶段（初始标记→并发标记→重新标记→并发清除）完全没记**——CMS 最高频考点，你记了它的缺点却没记它的流程
- G1 的 Young GC / Mixed GC / Full GC 具体触发与执行流程没有展开（MixedGC 只记了"是什么"）
- ZGC / Shenandoah 没记（演进表记到了 27+ 默认 G1，但新一代收集器是加分题）
- 三色标记 + SATB 没记（深挖题，可选）

### F. JVM 调优（37 图）——掌握度：★★☆☆☆ 你的自我感觉是对的，而且是最碎的区

**碎片化实证：** 37 张图里大量"单句卡片"——"JDK8 默认 GC 就是 ParallelGC"一张、"适合小内存单核"一张、"GC时间不可控"一张、"设置垃圾回收器--影响STW"一张……知识点密度极低，散落无主线。

**已掌握（散点）：**
- 调优参数三组：堆参数（-Xms/-Xmx/-XX:NewSize/-XX:NewRatio/-XX:SurvivorRatio）、收集器参数、并行参数（MaxGCPauseMillis/GCTimeRatio/ParallelGCThreads）、日志参数（PrintGC 系列）
- GCTimeRatio=99 → GC 占 1% 的公式记过
- STW 概念、并行（STW 下多 GC 线程）vs 并发（GC 与应用线程同跑）的区分——你专门记了"很多人弄混"，这里你是对的
- 各收集器特点四句总结（Serial 单线程小内存/Parallel 吞吐/CMS 低停顿/G1 混合）
- **生产 Docker 参数 12 条逐条解释**（-Xms1024m -Xmx4096m、Metaspace 128/512、G1+MaxGCPauseMillis=200、HeapDumpOnOutOfMemoryError、HeapDumpPath 容器丢失坑、egd urandom、file.encoding、达梦 dm_svc）——**全画布最有面试价值的素材，你实际调过优，这是"讲得出细节"的底气**
- 调优思路的三个碎片：分析 GC 日志发现频繁 Full GC→关注老年代 / Heap dump 找泄漏源头（未关闭资源、长生命周期大对象）/ 代码优化

**薄弱/缺失（这是你"感觉没弄明白"的真正原因）：**
1. **没有方法论主线**——你自己的调优思路被拆成 3 张孤图，参数、收集器、STW、思路各自为战。缺一条"定目标→监控→定位→调整→验证"的骨架把 37 张散图挂上去
2. **GC 日志解读完全没记**——记了怎么打印（PrintGCDetails 等 4 个参数），没记怎么读（各字段含义、怎么看频繁 Full GC、怎么看晋升）
3. **工具链零记录**——jps/jstat/jmap/jstack/jcmd/Arthas 在 JVM 区一张图都没有，而"频繁 Full GC 怎么排查"必然用到工具
4. **OOM 类型大全没记**——只记了堆 OOM 一句（Java 基础区那个"大量对象长时间无回收导致 oom"），Metaspace OOM、unable to create native thread、GC overhead limit exceeded 都没有
5. **容器化 JVM 内存感知没记**——你生产在 Docker 里手动 -Xmx4096m + 容器 5~6G，但 -XX:+UseContainerSupport、MaxRAMPercentage 这套容器感知参数没进笔记
6. 内存泄漏 vs 内存溢出的区分没显式记（你 Heap dump 那张图隐含了，但没有明确对比）
